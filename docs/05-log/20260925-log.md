ผู้ใช้อ่านทวนแล้วและยืนยันว่าเรียบร้อยก่อนบันทึก log นี้

**แหล่งที่อ่าน**: `01-spec/` ทั้ง 5 ไฟล์ (ส่วนขอบเขต/นอกขอบเขต), `backlog.md`, `user-journeys.md` (Actor/Persona),

`apps/web/server/index.ts` + `routes/*`, `apps/mobile/app/*`, `packages/shared-types/src/entities/*`,
`firestore.rules`

**เนื้อหาใน `spec.md`**:

1. **ภาพรวม + ตาราง Feature** — 16 Feature ID (ONB-0…INT-3) พร้อม MoSCoW จาก `backlog.md`
2. **หน้าจอ 17 หน้า** — เว็บ 15 หน้า (auth 4, onboarding 4, แท็บ 4, workout 2, log history 1) และมือถือ
   companion 2 หน้า (กรอกรหัสจับคู่, เชื่อมต่ออุปกรณ์) ทุกหน้าผูก route/ไฟล์/Feature ID/ระดับการเข้าถึง
   (`RequireAuth`/`RequireOnboarding`)/prototype
3. **โครงสร้างข้อมูล** — แผนผัง Firestore (`users/{userId}` + 5 subcollection, `pairingCodes`), ตาราง entity 16 ตัว
   จาก `shared-types` และตาราง API endpoint แยกตาม HLA component
4. **บทบาทผู้ใช้** — มีบทบาทมนุษย์เดียวคือ "ผู้ใช้" (ไม่มี admin/RBAC; Firestore rules เป็น owner-only) แบ่งตาม
   สถานะการใช้งาน 4 แบบ (ผู้เยี่ยมชม / ผู้ใช้ใหม่ / ผู้ใช้ประจำ / ผู้ใช้ที่มีอุปกรณ์) และแยกระบบภายนอกไว้ต่างหาก
5. **Out of scope** — 3 กลุ่ม: (ก) ตามที่ `01-spec/` ระบุ (MFA, social login อื่น, account switching, food-intake
   logging, offline, SLA ระดับ production), (ข) ตามการแบ่งหน้าที่เว็บ/มือถือในโค้ด (เว็บไม่ทำ Bluetooth/HealthKit,
   มือถือไม่มี auth/core loop, ไม่มีระบบหลังบ้าน, ไม่มี Cloud Functions), (ค) อยู่ในขอบเขตแต่ยังทำไม่เสร็จ
   (INT-2/INT-3 บนมือถือยังเป็นโครง, Firestore rules ยังเป็น scaffold, pairing code ยังไม่มี rate limit, ยังไม่มี
   test suite)

**การตีความ**: "Module นี้" ตีความว่าหมายถึงทั้ง `smartfit_daily_app/` (web + mobile + shared-types)
