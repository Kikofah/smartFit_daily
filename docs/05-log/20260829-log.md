### Ask-user protocol — 2 ประเด็นออกแบบ (ผู้ใช้ตอบแล้ว)

1. **signup/login ควรแยก endpoint ต่อวิธีหรือรวมเป็น endpoint เดียว** — เสนอ 3 ทางเลือก (รวม 1 endpoint /
   แยก 3 endpoint ต่อวิธี / hybrid path parameter) พร้อมคำแนะนำทางเลือก "แยก 3 endpoint" (เพราะ HLA §6.4
   เองก็ระบุพฤติกรรม error ของ external IdP ต่างจาก email/password ชัดเจน) — **ผู้ใช้ยืนยันแยก 3 endpoint**
2. **`database-schema.md` ต้องมีตาราง `user_account` แยกหรือไม่** — เสนอ 4 ทางเลือก (ไม่มีตารางแยก / ตาราง
   เต็มรูปแบบรวม session state / thin identity anchor / merge เข้า `user_profile`) พร้อมคำแนะนำ "thin
   identity anchor" (แก้ปัญหาเชิงโครงสร้างที่พบระหว่าง audit: `user_profile` ปัจจุบันบังคับทุก field เป็น
   required ทำให้สร้างไม่ได้ทันทีตอน signup ก่อนทำ ONB-1 เสร็จ จึงต้องมี identity anchor ที่มีอยู่ตั้งแต่
   signup) — **ผู้ใช้ยืนยัน thin identity anchor**
