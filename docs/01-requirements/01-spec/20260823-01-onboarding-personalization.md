# 20260823-01 - Onboarding & Personalization

- **ประเภท:** Feature
- **สถานะเอกสาร:** Ready
- **วันที่สร้าง:** 2026-08-23

## ขอบเขต (Scope)

**อยู่ในขอบเขต (In scope)**

- ผู้ใช้ใหม่กรอกข้อมูลร่างกาย (อายุ เพศ น้ำหนัก ส่วนสูง ระดับกิจกรรม) เพื่อคำนวณ BMR/TDEE
- ผู้ใช้เลือกอุปกรณ์ที่มี (ไม่มีอุปกรณ์ / ดัมเบล / ยิมครบชุด) เพื่อกรองวิดีโอที่แนะนำได้จริง
- ผู้ใช้ตั้งเป้าหมายหลัก (ลดน้ำหนัก / กระชับสัดส่วน / เพิ่มความอึด) แล้วระบบแปลงเป็นค่าแคลอรี่เป้าหมายรายวัน

**นอกขอบเขต (Out of scope)**

- ยังไม่ได้ระบุไว้ในเอกสารต้นฉบับ (product backlog เดิม) — ถ้ามีขอบเขตที่ต้องการตัดออกอย่างชัดเจน ให้ระบุเพิ่มก่อนเข้าสู่ 02-design

## รายละเอียด (Description)

Onboarding เป็นขั้นตอนแรกที่ผู้ใช้ใหม่ทุกคนต้องผ่านก่อนใช้งานฟีเจอร์อื่น ผลลัพธ์จากขั้นตอนนี้ (TDEE,
โปรไฟล์อุปกรณ์, เป้าหมายแคลอรี่รายวัน) เป็น input ที่ [Daily YouTube Recommendation](20260823-02-daily-youtube-recommendation.md)
และ [Planner & Logging](20260823-03-planner-logging.md) ต้องใช้ต่อ

## เงื่อนไข/กติกาทางธุรกิจ (Business Rules)

1. **REQ-01**: คำนวณ BMR/TDEE จากอายุ เพศ น้ำหนัก ส่วนสูง ระดับกิจกรรม (เช่น สูตร Mifflin-St Jeor)
2. **REQ-02**: แปลงเป้าหมาย (ลด/กระชับ/เพิ่มความอึด) เป็นค่าส่วนต่างแคลอรี่ (deficit/surplus) ต่อวัน
3. **REQ-03**: บันทึกโปรไฟล์อุปกรณ์ผู้ใช้ และใช้เป็นตัวกรองวิดีโอที่แนะนำ

## Acceptance Criteria

- [ ] ผู้ใช้กรอกอายุ เพศ น้ำหนัก ส่วนสูง ระดับกิจกรรม แล้วระบบคำนวณ TDEE ให้อัตโนมัติ (REQ-01)
- [ ] ผู้ใช้เลือกอุปกรณ์ที่มีได้ และค่านี้ถูกใช้กรองวิดีโอที่แนะนำในทุก session ถัดไป (REQ-03)
- [ ] ผู้ใช้เลือกเป้าหมายหลักได้ 1 ใน 3 แบบ และระบบแปลงเป็นค่าแคลอรี่เป้าหมายรายวันที่เจาะจง (REQ-02)

ดูรายละเอียดแบบ Given-When-Then เต็มรูปแบบที่ [acceptance-criteria.md](../acceptance-criteria.md)

## ข้อสมมติฐาน/การตัดสินใจที่ยืนยันแล้ว

ยืนยันกับผู้ใช้งานแล้วเมื่อ 2026-08-23 (ผ่าน audit ของ skill `feature-list-journey`, ดูรายละเอียดเต็มใน
[User Journey ของ ONB-3](../../02-design/01-prototypes/user-journeys.md#onb-3--ตั้งเป้าหมายหลัก-req-02)):

- **ค่า deficit/surplus ต่อวัน (REQ-02)**: ใช้ค่าคงที่ตายตัวต่อเป้าหมาย — ลดน้ำหนัก = TDEE − 500 kcal/วัน,
  กระชับสัดส่วน = TDEE + 0 kcal/วัน (maintenance), เพิ่มความอึด = TDEE + 300 kcal/วัน — พร้อม safety floor
  ห้ามต่ำกว่า 1,200–1,500 kcal/วัน (ใช้ค่าคงที่ 7,700 kcal ≈ 1 กก. ไขมัน ร่วมกับ Smart Integrations/INT-1)
- **การเลือกอุปกรณ์แบบ multi-select (REQ-03)**: backfill เข้าเอกสารนี้จาก full consistency audit ของ skill
  `feature-list-journey` วันที่ 2026-08-27 — ไม่ใช่ ask-user round ใหม่ แต่เป็นการยืนยัน "spec ตามหลัง"
  (reverse-drift ที่ไม่ขัดแย้งกับสิ่งใด): `user-journeys.md#onb-2` ระบุอยู่แล้วว่า "เลือกได้มากกว่า 1
  ถ้าจำเป็น" และ prototype `v1/02-onboarding-equipment.html` กับ test case `TC-ONB-2-002` ก็ implement/ทดสอบ
  ตามนั้นสอดคล้องกันทั้งคู่อยู่แล้วก่อน audit นี้ — จึงยืนยันเป็นทางการว่า **ผู้ใช้เลือกอุปกรณ์ได้มากกว่า 1
  ประเภทพร้อมกัน** (เช่น ดัมเบล + ยิมครบชุด) ไม่ใช่ single-select ส่วนกติกา mutual-exclusion ระหว่าง
  "ไม่มีอุปกรณ์" กับอุปกรณ์เฉพาะเจาะจง (เลือกพร้อมกันไม่ได้) ยังคงเป็นการตัดสินใจของ prototype เท่านั้น
  ไม่ใช่ข้อกำหนดที่ resolve ในเอกสารนี้
- **ช่องกรอกน้ำหนักเป้าหมาย (target weight) ใน ONB-3/REQ-02**: ยืนยันกับผู้ใช้งานแล้วเมื่อ 2026-08-28
  (ถามผ่าน AskUserQuestion โดย `architecture-builder` ระหว่างเตรียม High-Level Architecture — เลือก
  **ตัวเลือก (A) เพิ่มช่องกรอกน้ำหนักเป้าหมายใน ONB-3**) — gap ที่พบ: `user-journeys.md`'s INT-1 ระบุ
  precondition ว่า "มีเป้าหมายน้ำหนัก (จาก ONB-3)" แต่ ONB-3 เดิมให้ผู้ใช้เลือกแค่ **ประเภทเป้าหมาย**
  (ลดน้ำหนัก/กระชับสัดส่วน/เพิ่มความอึด) แล้วแปลงเป็นค่า kcal offset เท่านั้น ไม่มีขั้นตอนกรอกตัวเลขน้ำหนัก
  เป้าหมายจริงเลย ซึ่ง INT-1 (พยากรณ์วันถึงเป้าหมายน้ำหนัก) ต้องใช้ค่านี้จริงในการคำนวณ — เพิ่มขั้นตอนใน
  ONB-3 ดังนี้:
  - เมื่อผู้ใช้เลือกเป้าหมาย **"ลดน้ำหนัก"**: ระบบให้กรอกตัวเลขน้ำหนักเป้าหมาย (target weight, kg)
    เป็น **ช่องบังคับ (mandatory)** เพราะเป็นกรณีเดียวที่เป้าหมายผูกกับตัวเลขน้ำหนักโดยตรงและเป็นกรณีที่
    INT-1 ต้องใช้จริง
  - เมื่อผู้ใช้เลือกเป้าหมาย **"กระชับสัดส่วน"** หรือ **"เพิ่มความอึด"**: ช่องกรอกน้ำหนักเป้าหมายเป็น
    **ทางเลือก (non-mandatory)** — ดุลยพินิจของ `feature-list-journey` เพราะเป้าหมายทั้งสองแบบนี้ไม่ได้
    นิยามด้วยตัวเลขน้ำหนักโดยตรง (maintenance/เพิ่มความอึดไม่จำเป็นต้องมีเป้าหมายน้ำหนักที่ชัดเจน) ถ้าผู้ใช้
    ข้ามช่องนี้ INT-1 จะยังใช้งานไม่ได้สำหรับผู้ใช้คนนั้นจนกว่าจะกรอกภายหลัง (ดู Alt/Edge Case ของ INT-1
    ที่ปรับตาม)
  - ค่านี้ถูกบันทึกลงโปรไฟล์ผู้ใช้พร้อมกับเป้าหมายแคลอรี่รายวัน และเป็นแหล่งที่มาจริงของ precondition
    "มีเป้าหมายน้ำหนัก" ที่ [INT-1](../../02-design/01-prototypes/user-journeys.md#int-1--พยากรณ์วันถึงเป้าหมายน้ำหนัก-req-11)
    ใช้อ้างอิง (แก้ไขให้ตรงกันแล้วในเอกสารนั้น)

## จุดที่ยังไม่ได้ระบุ / ควรยืนยันเพิ่มเติม

- **ONB-3 (REQ-02)**: กรณีผู้ใช้เลือกเป้าหมาย "กระชับสัดส่วน"/"เพิ่มความอึด" แล้วข้ามช่องน้ำหนักเป้าหมาย
  (non-mandatory) — ยังไม่ได้ระบุว่าระบบควรเตือน/แนะนำให้กรอกภายหลังผ่านช่องทางไหน (เช่น banner ใน
  หน้า Progress/Insights) หรือปล่อยให้ INT-1 แสดง empty state เฉยๆ จนกว่าผู้ใช้จะกรอกเอง
