# 20260823-03 - Planner & Logging

- **ประเภท:** Feature
- **สถานะเอกสาร:** Draft
- **วันที่สร้าง:** 2026-08-23

## ขอบเขต (Scope)

**อยู่ในขอบเขต (In scope)**

- ปฏิทินวางแผนออกกำลังกายรายสัปดาห์
- โหมด Cheat Day / Rest Day ที่ไม่กระทบสถิติ
- บันทึกสถิติ (streak, นาทีที่ออกกำลังกาย, แคลอรี่สะสม)

**นอกขอบเขต (Out of scope)**

- ยังไม่ได้ระบุไว้ในเอกสารต้นฉบับ (product backlog เดิม)

## รายละเอียด (Description)

ผู้ใช้วางแผนล่วงหน้าเป็นสัปดาห์ผ่านปฏิทิน ตั้ง Cheat Day/Rest Day ได้โดยไม่เสียสถิติ และเมื่อออกกำลังกาย
ครบเป้าหมายรายวัน (เทียบแคลอรี่จริงจาก [Daily YouTube Recommendation](20260823-02-daily-youtube-recommendation.md))
ระบบจะบันทึก log และอัปเดต streak ต่อเนื่อง

## เงื่อนไข/กติกาทางธุรกิจ (Business Rules)

1. **REQ-08**: แสดงปฏิทินรายสัปดาห์ที่กำหนดวันออกกำลังกายล่วงหน้าได้
2. **REQ-09**: โหมด Cheat Day/Rest Day ต้องหยุดนับเป้าหมายแคลอรี่ของวันนั้นโดยไม่ทำให้ streak ขาด
3. **REQ-10**: บันทึก log รายวัน (นาทีออกกำลังกาย, แคลอรี่สะสม) เมื่อผู้ใช้ทำครบเป้าหมาย

## Acceptance Criteria

- [ ] ผู้ใช้เห็นและกำหนดแผนออกกำลังกายล่วงหน้าเป็นสัปดาห์ได้ (REQ-08)
- [ ] ตั้ง Cheat Day/Rest Day แล้วเป้าหมายแคลอรี่ของวันนั้นหยุดนับ และ streak ไม่ขาด (REQ-09)
- [ ] ออกกำลังกายครบเป้าหมายแล้วระบบบันทึก log (นาที, แคลอรี่สะสม) อัตโนมัติ (REQ-10)
- [ ] ผู้ใช้เห็น streak การออกกำลังกายต่อเนื่องของตนเอง (REQ-09, REQ-10)

ดูรายละเอียดแบบ Given-When-Then เต็มรูปแบบที่ [acceptance-criteria.md](../acceptance-criteria.md)

## ข้อสมมติฐาน/การตัดสินใจที่ยืนยันแล้ว

ยืนยันกับผู้ใช้งานแล้วเมื่อ 2026-08-23 (ผ่าน audit ของ skill `feature-list-journey`):

- **Cheat/Rest Day ในวันที่มี log อยู่แล้ว (REQ-09)** — ดูรายละเอียดเต็มใน
  [User Journey ของ PLN-2](../../02-design/01-prototypes/user-journeys.md#pln-2--โหมด-cheat-day--rest-day-req-09):
  เก็บ log เดิมไว้ ไม่ลบทิ้ง และถือว่าวันนั้น "ครบเป้าหมาย" (completed) แทนที่จะเป็นแค่ "excluded" —
  Cheat/Rest Day มีผลเปลี่ยนสถานะเฉพาะวันที่ยังไม่มี log เท่านั้น
- **วันที่ออกกำลังกายไม่ครบเป้าหมาย ทำให้ streak ขาดหรือไม่ (REQ-10)** — ดูรายละเอียดเต็มใน
  [User Journey ของ PLN-3](../../02-design/01-prototypes/user-journeys.md#pln-3--บันทึกผลรายวันเมื่อครบเป้าหมาย-req-10)
  และ [PLN-4](../../02-design/01-prototypes/user-journeys.md#pln-4--ติดตาม-streak-ต่อเนื่อง-req-09-req-10):
  ใช้กติกา all-or-nothing เข้มงวด วันที่ log แบบ "ไม่ครบเป้าหมาย" ทำให้ streak ขาดทันที เหมือนไม่มี log เลย
  (ไม่มี partial credit หรือ grace miss ใด ๆ ในเวอร์ชันนี้)
- **นิยามของ "ปฏิทินรายสัปดาห์" (PLN-1/REQ-08)** — ยืนยันกับผู้ใช้งานแล้วเมื่อ 2026-08-27 (ตอบคำถามที่ตั้งไว้
  จาก full consistency audit ของ skill `feature-list-journey` วันเดียวกัน ซึ่งพบว่า `backlog.md`/
  `user-journeys.md` เดิมเขียนว่า "7 วันข้างหน้า" (rolling window) ขัดกับ prototype
  `v1/08-weekly-planner.html` และ test case `TC-PLN-1-001`–`003` ที่ implement/ทดสอบเป็น fixed calendar
  week อยู่แล้ว — เลือกตัวเลือก (A) ยึดตาม prototype/test case ที่มีอยู่แล้ว): ปฏิทินของ PLN-1 คือ
  **fixed calendar week แบบจันทร์–อาทิตย์** (ไม่ใช่ rolling 7-day-forward window จากวันนี้) โดย
  **วันที่ผ่านมาแล้วในสัปดาห์นั้นซึ่งมี log อยู่ก่อนแล้ว จะแสดงเป็น read-only (แก้ไขไม่ได้)** ส่วนวันนี้และ
  วันในอนาคตของสัปดาห์เดียวกัน (ยังไม่มี log) ยังคงกำหนด/แก้ไขแผนได้ตามปกติ — คำตอบนี้ resolve
  open question เดิมเรื่อง "ผู้ใช้แก้ไขแผนของวันที่ผ่านไปแล้ว (มี log แล้ว) ได้หรือไม่" ไปพร้อมกันด้วย
  (คำตอบ = ไม่ได้ เป็น read-only)
- **ขอบเขตของการตั้ง/เปลี่ยน Cheat/Rest Day ย้อนหลังทับ log ที่มีอยู่แล้ว (PLN-2/REQ-09)** — ยืนยันกับ
  ผู้ใช้งานแล้วเมื่อ 2026-08-28 ต่อเนื่องจาก decision ของ PLN-1 ด้านบน: `test-suite-builder` ตรวจพบระหว่าง
  self-freshness audit ว่า test case เดิม (`TC-PLN-2-003`/`004`) สมมติว่าผู้ใช้ตั้ง Cheat/Rest Day ย้อนหลัง
  ผ่านการแตะวันในอดีตของปฏิทิน (เช่น วันอังคาร/จันทร์ที่ผ่านมาแล้วและมี log อยู่ก่อน) ซึ่งขัดกับ decision ของ
  PLN-1 ที่ mark วันในอดีต+มี log เป็น read-only แบบไม่มีข้อยกเว้น — ถามผู้ใช้ 3 ทางเลือกแล้ว **เลือกตัวเลือก
  (A) จำกัดเฉพาะวันนี้**: การตั้ง/เปลี่ยน Cheat/Rest Day ที่ทับ log ซึ่งมีอยู่แล้วนั้น **ทำได้เฉพาะ "วันนี้"
  เท่านั้น (เช่น หลังออกกำลังกายเสร็จแล้วในวันเดียวกัน)** ไม่สามารถทำผ่านการแตะวันในอดีตของสัปดาห์จากปฏิทิน
  (PLN-1) ได้อีกต่อไป แม้จะอยู่ใน fixed calendar week เดียวกันก็ตาม — วันในอดีตที่มี log ยังคงเป็น read-only
  ตามกติกาของ PLN-1 **ไม่มีข้อยกเว้นสำหรับ PLN-2** ส่วน flow ของ Cheat/Rest Day ที่ตั้งบนวันที่ยังไม่มี log
  เลย (วันนี้ก่อนออกกำลังกาย หรือวันในอนาคต) ยังคงทำได้ตามปกติผ่านทั้งปฏิทิน (PLN-1) และ Daily Dashboard
  ไม่เปลี่ยนแปลง
